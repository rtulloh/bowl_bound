## Description

Review of 5294eb8..44d3438 reproduced changed future coaching from a valid baseline-generated save that still loads. The v1 RNG code removes new observation fields, and observe_policy restricts defense calls for v1–v8, but it leaves new offense/special/game-action menus in the hashed observation. Q, RZDZ, onside, bounds and elected-safety additions therefore change even legacy seeded choices.

Synthetic reproduction: using the actual 5294eb8 implementation and public sample_teams(), create a regulation SavedGame with seed=7, coach_seed=31 and coach_policy omitted (baseline); choose the first enabled opening election, execute the kickoff and complete its pending choices, then save. `plan_turn(view, "home", game._coach).computer_choice.key` is "2" at 5294eb8. Load the unchanged save with current code and the same public charts: it remains policy baseline, but its next computer call is "8". No future gameplay dice were consumed to compare plans.

The policy-freezing comments in coaching.py and reproducible-v1 guarantees in docs/coaching.md are therefore false across versions. Current save tests compare two games running the new implementation, so both produce the same changed call and the tests pass. This is distinct from DEV-053, which concerns saves that fail to load.

Assigned to milestone 23 as compatibility follow-up.

## Resolution / verification

- Define and preserve each legacy policy observation/menu contract, including all action families used in the RNG hash and candidate selection.
- Add cross-version golden continuation tests generated by the prior implementation; do not regenerate both expected and actual calls under current code.
- Verify legacy baseline, chart and difficulty policies while keeping v9 access to the new actions.
