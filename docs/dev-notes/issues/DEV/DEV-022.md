## Description

special_teams._recovery and turnovers.resolve_fumble repeat the end-line test, depth roll and recovery gates; _accepted_return/_return_cell and enforce_return_penalty/_apply_return_yards repeat the midpoint and touchback-versus-safety classification with divergent end-zone handling. Placeholder states (start_drive at 99 plus origin) encode three coordinate conventions; TurnoverResolution has 15 fields with overlapping pairs; resolve_fumble exposes a private _depth parameter; magic numbers 93, 99, 80, 9, -10 and 110 recur; session gain handling treats pending results with no numeric yardage as zero.

## Resolution / verification

- Shared `resolve_recovery` handles end-line, depth and recovery rolls for scrimmage and special-teams fumbles. `ReturnOrigin` and validated `ReturnStart` preserve actual end-zone coordinates beside representable field state. Turnover penalties and end-zone recovery facts are grouped; the public fumble API no longer exposes recursive chain depth. Field-coordinate constants replace repeated literals.
- Session gain handling now rejects pending results without resolved yardage instead of silently reporting zero; penalty previews avoid that fallback. The unresolved-location text in `_penalty_result_text` remains intentionally because penalty choices can be shown before variable turnover locations are rolled.
- Verified at `c1e81ff`: 1,045 tests passed across the turnover, return, special-teams, penalty, timing, regulation, overtime, statistics and commentary engine suites. Ruff check/format and `git diff --check` passed.
