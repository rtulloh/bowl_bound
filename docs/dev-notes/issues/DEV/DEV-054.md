## Description

Review of 5294eb8..44d3438 reproduced a period-score attribution flaw in `scripts/run_local_season.py:421-430`. The runner credits score deltas to `_period_number(view)` captured before executing the action. A snap submitted during clock_choice can first exhaust Q1/Q3, then score in Q2/Q4; the delta is credited to the old quarter. The reconciliation only checks sums, so the incorrect quarter breakdown passes.

Synthetic reproduction using existing helpers: `new_game(clock=Clock(1, 30), plays={Play.ONE: yards(0), Play.NINE: yards(100)})`; complete `kickoff(game)`, snap 1/A with `play_dice()`, retain before=game.view(), then snap 9/A. `_period_number(before)` is 1; the touchdown report is charged in `game.view().timing_log[-1].quarter == 2`. The runner would put its six points in Q1.

DEV-007/M32 acceptance claims per-period scoring reconciliation. Assigned to milestone 23 as follow-up verification work.

## Resolution / verification

- Attribute each scoring event to the period in which its play actually executes, including implicit quarter boundaries and required conversions.
- Add full runner tests that score on the first snap after Q1/Q3 expiration and assert exact period totals, not just their sum.
