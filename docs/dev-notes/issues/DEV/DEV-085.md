## Description

The hand-maintained release/manifest.json allowlist omitted bowl_bound/rules_summary.py after backend/app.py began importing it. The isolated release-runtime import test failed with 'Missing release module: bowl_bound.rules_summary', so a packaged build would have crashed at startup. No completeness guard existed to catch a new runtime module being added without a manifest entry.

## Resolution / verification

- Add the missing module to release/manifest.json. Add a regression test that walks local imports from the runtime entry points (backend/app.py, backend/launcher.py, bowl_bound/cli.py) and fails when a reachable module is absent from the allowlist. Verify the test fails with the entry removed and passes with it restored. Run the full release-package suite and Ruff.

Root cause: `release/manifest.json` is a hand-maintained sorted allowlist with no
completeness check, so adding `bowl_bound/rules_summary.py` (imported by
`backend/app.py`) silently broke the isolated release runtime. Two other
`bowl_bound` modules are absent by design: `coaching_audit.py` and
`coaching_audit_sampling.py` are development-only and unreachable from the
runtime entry points.

Fixed by adding `bowl_bound/rules_summary.py` to the runtime allowlist and adding
`test_manifest_lists_every_runtime_reachable_local_module`, which walks local
imports from `backend/app.py`, `backend/launcher.py` and `bowl_bound/cli.py` and
fails when a reachable module is missing from the manifest. Verified red-first by
removing the entry (test failed naming `bowl_bound/rules_summary.py`) and green
after restoring it.
