## Description

Bowl Bound and Paydirt both default to local port 8000, preventing ordinary
simultaneous web play on the same computer. The owner requested Bowl Bound use
8001 and explicitly include this change in the next release, 1.0.0.

## Resolution / verification

- Default both the standalone/source production launcher and `python -m backend`
  to local port 8001. The auto-opened and printed browser URL must match the
  actual listener. Keep explicit `--port` overrides working.
- Point the frontend development API proxy at Bowl Bound's new default. Update
  current player/setup/version links and occupied-port guidance; a collision
  message must suggest a different port, such as 8002.
- Preserve local-only binding, resource lookup, lifecycle and failure behavior.
  Paydirt keeps its existing 8000 default; no Paydirt files need changing.
- Demonstrate default-port failures before implementation, then pass launcher
  lifecycle, explicit-override, API, packaging and applicable frontend checks.
  Verify a Bowl Bound default server can run while port 8000 is occupied.
- Include the change in the 1.0.0 integration, release notes and final release
  regression/build checks. Existing running games are not moved or stopped by
  changing the future default.

## Comments

24 launcher tests pass; the cumulative launcher/API/packaging/release-metadata/
player-doc/issue checks pass 100 tests. All 158 frontend tests and the production
frontend build pass. Ruff checks/formatting and whitespace checks pass.

An actual subprocess startup check, using only fictional sample bundles, starts
each entry point on default 8001 while an existing HTTP service remains on 8000.
Both serve /api/health and /api/version successfully; the existing service's
version-endpoint response stays unchanged. Only these temporary test servers
were stopped. Explicit port override, occupied-port failure, local binding and
browser/lifecycle controls remain covered. The actual Vite config imports with
API proxy http://localhost:8001.

This is a focused implementation checkpoint for 1.0.0. Final integration/native
release checks and owner play-test confirmation remain pending; keep the ticket
open until those assigned acceptance steps and tested commit references are
