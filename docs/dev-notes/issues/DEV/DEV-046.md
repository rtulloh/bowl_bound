## Description

The player index links docs/versioning.md, which explains PEP440, Python/npm/OpenAPI fields, DISPLAY_VERSION, engine profile bowl-bound-m21-v1 and immutable release-tag workflow. docs/playing.md explains 0.3/0.5/0.7 situational weighting and bounded chart estimates. These details do not tell a typical player how to find their version, choose a difficulty or preserve saves. docs/startup.md also discusses Vite/reloaders/child servers and interpreter selection. This is a concrete part of the owner-reported verbosity concern, distinct from navigation/onboarding structure.

## Resolution / verification

- Make player version help answer only how to find/report the displayed version, back up saves before updates, and follow release-specific compatibility notes. Move version mapping, engine-profile/schema details and tag policy to maintainer/API documentation.
- Describe Easy/Medium/Hard in terms of the experience and coaching decisions, keeping Medium as default and unchanged dice odds. Move weighting/estimator details to the coaching reference without changing gameplay.
- Move runtime process/interpreter implementation details out of the ordinary startup path while preserving useful --port, --no-browser and --seasons options.
- Retain required license/privacy information concisely; do not delete owner-requested security troubleshooting or turn a current limitation into an unsupported promise.
