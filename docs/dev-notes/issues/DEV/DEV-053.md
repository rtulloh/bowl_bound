## Description

Review of 5294eb8..44d3438 generated real saves with the unchanged implementation at 5294eb8 and loaded them with 44d3438, using the same Python 3.12 runtime and public `sample_teams()`. Fresh drive, pending opening kickoff, and regulation after an ordinary snap all raise SaveFormatError. Opening-toss and post-kickoff saves load, so the existing compatibility checks cover only some states.

Reproduction: extract `git archive 5294eb8 bowl_bound` into a temporary directory. Using that version, create `SavedGame.new(*sample_teams(), home_id="2007/a", away_id="2007/b", seed=7, coach_seed=31, mode="drive")` and save it. Current `loads_game` rejects it with the identical sample charts. Repeat with mode=regulation, accept the first enabled opening choice, then save before `kick("kickoff")`; this also fails. A regulation save after resolving the kickoff and `snap("1", "A")` fails too.

`save_game.py` accepts M21 profiles but none of its digest projections recreates all post-M27/pre-M22 menus: onside actions remain, while `_legacy_m27_view_digest` restores old runoff choices that were already absent at the reviewed baseline. DEV-052 only tests a historical fixture. `docs/saves.md` promises legacy M21 loading with the original defense profile. Assigned to milestone 23 as compatibility regression follow-up.

## Resolution / verification

- Add genuine baseline-generated synthetic fixtures for drive, opening kickoff, clock choice, penalty and conversion states; preserve their semantic digests.
- Implement a projection appropriate to M21/post-M27 saves without stripping actual gameplay differences or weakening corruption checks.
- Verify continuation as well as loading and document the compatibility boundary.
