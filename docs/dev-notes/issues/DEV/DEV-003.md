## Description

`bowl_bound/session.py` is about 1,500 lines; `snap` and `decide` are each 150-190 lines and
`_PendingDecision` is a flag-tagged union (turnover, turnover_resolution, turnover_location,
dice) guarded by RuntimeErrors at 697-698, 727-728 and 772-776, with choice-id string parsing
at 730-733 and 808. Related findings: `_hurried_play` is not initialised in `__init__`
(534, 784); `assert` is used for control-flow invariants (session 1148, regulation 557/567,
penalty_yardage 72-88) and disappears under `-O`; dead or test-only code includes
`ResultKind.PUNT_REFERENCE`, `Transition.description`, `game_state.describe`,
`prepare_hail_mary` and the unused resolve_kickoff/punt/field_goal helpers; the 1940-2023
season bounds are hard-coded in four modules; `session._status` still says "Scoring demo
complete. Post-score kickoff flow is not yet available."

## Resolution / verification

- Split pending decisions into typed dataclasses with their own apply methods, mirroring the
  closure-based SpecialTeamsPlay pattern, without changing engine behavior (existing suites
  plus full-game reconciliations must pass unchanged).
- Replace invariant asserts with explicit exceptions, initialise all session fields, delete or
  justify dead code, centralise season bounds, and refresh stale status wording.
- Keep docs/game-state.md and docs/turnovers.md in step with the structure.
