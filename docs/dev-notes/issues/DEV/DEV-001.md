## Description

The issue-index builder validates and indexes existing Markdown tickets but does not
create them. The user requests a standalone Python script they can run directly to
create a correctly structured ticket without manually copying and editing a file.
It must not require OpenCode, an AI agent, external issue tracking or a running app.

## Resolution / verification

Implemented and tested in `57b4dd6`. Standalone scripts/create_issue.py validates through the existing index builder, exclusively allocates IDs, regenerates the index and works outside the checkout. Collision, exhaustion, symlink, YAML, invalid-input and indexing-failure tests pass. DEV-012 was created through the CLI as a real invocation.

See [Milestone 19 acceptance](../../milestone-19.md) for the cumulative gates
and changed expectations. The committed implementation was rechecked with 99
focused Python tests. Awaiting owner play-test confirmation before closure.

- Provide a documented Python CLI under scripts/ with --help and actionable errors.
  Allow supplying the prefix/category, title, canonical milestone, description and
  acceptance criteria; support optional priority and tags with sensible defaults.
- Allocate the next available three-digit ID within the chosen prefix and create
  docs/dev-notes/issues/<PREFIX>/<ID>.md with valid front matter, open status, current
  creation date, empty resolution/closure fields, and all required body sections.
- Reuse existing ticket conventions and validation rather than maintaining a second
  incompatible schema or milestone list. Safely serialize titles and other inputs.
- Validate inputs before writing; reject path traversal, malformed prefixes and
  invalid milestones. Never overwrite existing tickets, including on an ID race;
  fail clearly or retry safely. Keep ticket content public-safe.
- Regenerate the issue index on successful creation using the existing builder,
  print the new ticket path/ID, and clearly report any indexing failure without
  silently discarding existing work or claiming success.
- Work when invoked from outside the repository by locating repository paths from
  the script itself. Use the project Python environment; no new service dependency.
- Add synthetic temporary-repository tests first for creation, numbering, metadata,
  invalid inputs, existing-file protection and index freshness. Document copyable
  standalone invocation examples and the difference from build_issue_index.py.
