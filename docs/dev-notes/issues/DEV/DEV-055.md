## Description

Review of 5294eb8..44d3438 found that `run_local_season` loads chart-only data via `catalog.load` and `_play_one` constructs `SavedGame.new` without home_privileges/away_privileges (`scripts/run_local_season.py:333-358,576`). Both default to empty even though new games enable Advanced II. A W-marked installed team therefore uses conditional Wild Card/Run/Pass rules in the audit, while CLI/API correctly pass metadata.defense_chart_markers and use free rules.

The runner accepts only `dict[str, TeamChart]`, so there is no path for the marker to survive. A wrong Wild Card against a four-yard run produces eight yards instead of four for such a team. The synthetic runner fixture metadata is always unmarked, masking this difference. Its standalone baseline coaches can select engine-offered advanced defenses, so the loss changes simulated game outcomes, not just labels.

This undermines RULE-019 and DEV-007 evidence claiming the production game paths were audited. Assigned to milestone 23 as follow-up to completed milestones 22/32.

## Resolution / verification

- Carry validated team metadata into every audit game, matching CLI/API construction.
- Add a synthetic W-marked versus unmarked runner test asserting free eligibility and the actual wrong-guess yardage.
- Record the coaching policy and rules/marker configuration used by each audit so evidence states its scope.
