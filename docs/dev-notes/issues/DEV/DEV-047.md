## Description

backend/launcher.py:86 chooses 127.0.0.1 for every host outside LOCAL_HOSTS. With --host 192.0.2.10 --allow-remote, the listener is bound only to that explicit address, but the printed URL and automatic browser target are http://127.0.0.1:8000. The documented opt-in can therefore open a connection-refused page or another local service. A no-network synthetic probe mocking socket/Uvicorn confirms the wrong advertised URL at ab4c70e. The current tests cover default loopback and refusal of implicit remote binding, not a successful explicit host.

## Resolution / verification

- Derive the displayed/browser address from the actual bind policy. Use an appropriate loopback address for wildcard binds; preserve specific IPv4/hostname binds and bracket specific IPv6 addresses.
- Add parameterized tests for default loopback, localhost, ::1, 0.0.0.0, ::, and explicit non-wildcard IPv4/IPv6 hosts, including the exact browser URL after readiness.
- Keep remote opt-in and its warning intact. Add a local integration smoke for a supported explicit address without exposing a service externally.
