## Description

The owner could not restore a private game through a long-lived local web play-test server. The recorded traceback fails after load while preparing a coaching response: a newly imported difficulty module expects razzle_context in an older in-memory observation model. Investigate and prove the mixed-module boundary with synthetic data, preserving both existing live games and strict save replay. This is separate from AI-033 selection correctness; a frozen snapshot server is the immediate containment.

## Resolution / verification

- The failure occurred while preparing the loaded game's coached response, not while rejecting its saved journal: a newly imported `difficulty.py` tried to remove `razzle_context` from an older in-memory `CoachObservation` shape. A synthetic pre-v11 model with the new module/frozen-v10 policy reproduces the exact `KeyError`; consistent current models with v10/v11 pass.
- Containment uses an untouched checkout of tested `97d9314` on a new local port, with its own built frontend and code import path. The original two live servers and their games remain intact. No game rules, replay validation or dictionary fallback were changed.
- The frozen server passed health/frontend checks and fictional Easy drive Save/Load for both human sides (HTTP 200). The owner's exact private save loaded and re-saved (HTTP 200); comparison differed only in `saved_at` and its integrity checksum. Gameplay, coaching, commands, dice and state semantics matched. No private content is copied into this ticket.
- Owner confirmed the saved game loads in the browser on 2026-11-03 and explicitly authorized closure. Maintained [startup guidance](../../../startup.md) now requires an isolated, fixed source snapshot for concurrent play testing.
