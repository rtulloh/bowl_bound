## Description

Backend/engine review findings for `backend/app.py` and `bowl_bound/save_game.py`:

- `save_game.SavedGame._execute:284-287` journals every rejected command. Nothing caps
  `_commands`, so repeated 409/422 requests (for example snapping a finished game) grow memory
  and, after `MAX_COMMANDS`, make an unchanged game unsaveable.
- `app.py:118-125,169-170`: the separate `seeds` dict is looked up after `_session`; eviction
  between the two lookups raises KeyError (500). `SavedGame.seed` already exists.
- `app.py:176-181`: report and view are taken under separate lock acquisitions, so concurrent
  requests on one game can return mismatched report/view pairs.
- `app.py:122-124`: eviction is FIFO by creation, not by activity; `app.py:32-33,256` use
  `re.match` with `$` (accepts a trailing newline) where `save_game` uses `fullmatch`;
  `_load` skips the symlink checks that `_team_folders` applies; non-load endpoints have no
  body-size bound if `--allow-remote` is used.
- docs/web-demo.md omits the 422 for `/action` outside regulation mode and the 422 (not 404)
  for missing teams during load.

## Resolution / verification

Implemented and tested in `57b4dd6`. Registry lookup/eviction is synchronized and LRU; seeds come from captured games, and command/report/view capture shares one per-game lock. No-op errors do not grow new journals; replay errors are retained. Identifier, symlink, in-flight eviction and streaming body-limit regressions pass. POST limits are 16 KiB normally and 2 MiB for save imports.

See [Milestone 19 acceptance](../../milestone-19.md) for the cumulative gates
and changed expectations. The committed implementation was rechecked with 99
focused Python tests. Awaiting owner play-test confirmation before closure.

- Add failing tests: many rejected snaps do not block `GET /api/games/{id}/save` or grow the
  journal; seed is served without a second map; report and view come from one lock scope.
- Skip journaling commands that provably consumed no dice or state, or cap error records;
  drop `seeds`; add a `SavedGame` method returning (report, view) atomically; use
  `move_to_end` on access; align id matching and symlink handling; consider a body-limit
  middleware for remote mode.
- Update docs/web-demo.md and docs/saves.md status-code tables.
