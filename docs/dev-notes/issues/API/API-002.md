## Description

GET /api/games/{id}?human_side, POST /coach and POST /decision?human_side call coach_view, coach_step and coach_execute, which raise ValueError or NoLegalAction from plan_turn. None are caught, so the API returns 500 while docs/coaching.md promises an empty legal set fails clearly. Reproduced with a synthetic game and a patched coordinator.

## Resolution / verification

- Commit `f2bdf50` maps coordinator `ValueError` (including `NoLegalAction`) from coached views and actions to HTTP 409 with a stable message that does not expose exception text. Invalid user decisions still return 422; engine conflicts retain their existing responses.
- Test-first evidence: all six new endpoint/error cases failed unchanged because exceptions escaped the API. Focused validation passed: 56 Python API tests, Ruff lint and formatting, and `git diff --check`.
- Awaiting owner play-test before closure.
