## Description

POST /snap accepts both calls on a game created with human_side=home, and /coach takes human_side in each request body, so a coached game can be driven manually or with alternating sides. Two back-to-back identical /coach requests both return 200 and resolve two plays; the browser's inFlight ref is the only guard. Local solitaire makes this self-cheating only, but the contract is undocumented and would be inherited by any remote use.

## Resolution / verification

- Decide and document: bind human_side at creation and reject mismatched requests, and accept an expected play number or idempotency token on /coach. Tests for manual snap on a coached game, alternating sides, missing human_side, concurrent duplicate coach posts, 16 KiB limit on /coach and /decision, load at exactly MAX_SAVE_BYTES and plus one, and fingerprint mismatch through the API.
