## Description

Owner alpha play-test feedback: engine narration currently prefixes the raw result summary with role labels and an illustrative-players disclaimer, rather than integrating player names into an announcer-style sentence. Prefer varied natural calls such as 'Dorian Reef is stopped for no gain!' or 'The defense holds firm! No gain for Dorian Reef.' Shared engine wording should improve CLI, API and web output without changing football results. Track as alpha acceptance follow-up to committed milestone 21a, not a reopening of its implementation history. Discussion only while release work is paused; no production wording changed.

## Resolution / verification

- Use engine-generated, outcome-specific template families for natural named and generic play-by-play; keep technical play/formation/state/trace information separate from the main spoken-style call.
- Vary wording deterministically without consuming gameplay or coaching randomness; repeated rendering and save/load must preserve their contracts.
- Describe only authoritative established facts: never invent a tackler, route, tackle break, injury, player statistic or uncommitted pending result; retain factual fallback for ambiguous outcomes.
- Keep illustrative-name disclosure available without mechanically prefixing every spoken call; review presentation and documentation before changing the disclosure.
- Review synthetic test expectations before red runs, preserve outcome/state/statistics/traces and old-save compatibility, then verify CLI/API/browser rendering and obtain owner play-test acceptance.
