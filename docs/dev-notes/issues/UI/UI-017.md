## Description

`frontend/src/api.js:21` fetches `/api/games/{id}/save` through `response.json()` and
`frontend/src/components/SaveControls.jsx:18-19` writes `JSON.stringify(data)` to the download.
The server emits a canonical document with an integrity digest and a Content-Disposition
filename that the browser ignores. JavaScript number parsing is lossy above 2^53 while the
API accepts seeds up to 2^63-1 and the loader requires exact integers, so a large-seed game
downloads a file that fails validation. This also contradicts the "saves are opaque engine
documents" comment and docs/saves.md.

## Resolution / verification

- Add a failing vitest asserting the downloaded blob equals the response body byte-for-byte
  and a browser test with a large explicit seed that saves and reloads successfully.
- Download the response as text/blob without parsing; keep the generic filename.
- Verify the invalid-upload and resume browser tests still pass.
