## Description

Allow web players to choose the home and away teams independently from any
installed eligible years, including the same school from two different years.
The designated home team's season governs both teams' gameplay rules, matching
the owner's requested Paydirt convention. Each team retains its own year's charts
and roster; selecting the rules year must not replace either team's data.

Existing foundations are already present: frontend/src/App.jsx lists the full
team catalog in both selectors, backend/app.py loads each requested team ID
independently, and docs/rules-profile.md freezes rules_season to the home team's
season. This ticket makes cross-year selection and the governing rules clear to
players and verifies the complete UI/API/engine/save flow. It does not claim that
cross-year engine support must be created from scratch.

## Resolution / verification

- Provide clear, independent home and away year/team selection, using filtering
  or grouping as appropriate for a large catalog. Changing one side's year must
  not restrict the other side to that year. Offer installed eligible bundles;
  do not imply charts exist for every historical year.
- Preserve stable season-qualified IDs and display each team's name and year.
  Allow two years of the same school without false duplicate-team rejection.
  Coordinate season-qualified in-game labels with UI-009.
- Before starting, show which home season governs the rules. Obtain the supported
  rules/profile summary from the backend. Designated home identity selects the
  rules for both sides, including supported kickoff/touchback, timing and overtime
  policies and the chosen regular-season/postseason game type. Possession, human
  control, newer year and neutral-site presentation must not choose the rules.
- Retain each team's selected year's chart and roster identity throughout the
  game and chart viewer. Never normalize the away team into the home season or
  import Paydirt/NFL rule behavior.
- Freeze the selected home-year rules at game creation. Save/load must retain and
  validate both season-qualified team identities, governing rules/profile and
  game type; changing setup controls later cannot change a saved game's rules.
- Unsupported home rules, unreadable bundles or incompatible competition must
  produce an actionable setup error. Do not silently use current-year, newer-team
  or NFL fallback rules or expose partially supported historical profiles.
- Write synthetic tests before behavior changes: mixed years in both home/away
  orientations, same school/different years, same-year controls, human home/away
  and manual modes, unsupported profiles, distinct chart identity and save/load.
  Cross a supported rules boundary and assert actual engine kickoff/touchback and
  overtime behavior follows the home year, rather than only checking a label.
- Run applicable frontend, API, rules/session and persistence regressions plus a
  real-engine browser play-test, then update setup/player documentation. Record
  tested commits before resolution and play-test confirmation before closure.
