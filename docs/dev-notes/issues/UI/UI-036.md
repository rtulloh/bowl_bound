## Description

The API already serializes `PlayReport.commentary` explicitly, and the browser renders the same commentary as the CLI. However, `PlayHighlights` still re-derives interception, fumble, touchdown, breakaway and touchback emphasis from outcome codes, statistics kind, trace section strings and timing flags. Move that classification to engine-owned report data and keep the browser responsible only for labels and visual styling.

## Resolution / verification

- `PlayReport.highlight_tags` classifies supported outcomes from engine-owned facts; API report and `view.log` serialization exposes the tags alongside the existing engine commentary. The property is derived and remains outside `asdict` and save data.
- The browser maps known tags to labels and colors without inspecting outcome, statistics, timing, or trace sections. Extended the frontend no-rules scan to reject those classifications.
- Updated the API contract docs. Existing commentary transport tests verify API narration matches the engine; frontend tests verify exact API text rendering and all highlight labels.
- Verified at `26f2d28`: `.venv/bin/python -m pytest tests/test_commentary.py tests/test_api_commentary.py tests/test_api_commentary_commands.py -q` (29 passed); `.venv/bin/python -m pytest tests/test_api*.py -q` (84 passed); Node 24.22.1 `npm test` (119 passed) and `npm run build` passed. Ruff check/format and `git diff --check` passed.

Awaiting play-test confirmation before closure.
