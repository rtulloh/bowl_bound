## Description

- `frontend/src/components/FootballField.jsx:8` renders a hard-coded "Drive complete" whenever
  `state` is null, which in regulation also happens after a try or safety while the engine
  status says a kickoff is required. Result wording must originate in the engine.
- `frontend/src/components/ClockChoices.jsx:13-16` uses radios whose `checked` state is pinned
  to `clock:runoff`; choosing another option fires the action but the group never reflects it,
  and the `clock:runoff` id is hard-coded in three places despite engine-supplied modifiers.
- `SaveControls.jsx:31-34` clears a file chosen while busy with no message, and
  `App.jsx:35` reports every setup failure as "server is not reachable".

Focus management and announcements are tracked separately in UI-006.

## Resolution / verification

- Add failing component tests: empty field shows the engine status text; clock choices expose
  accurate pressed/selected state (buttons or correctly controlled radios) with ids from the
  engine payload; busy-time file selection surfaces a message; setup errors show the real detail.
- Pass `view.status` to the field component or render an empty board; let the engine flag
  the default modifier instead of hard-coding its id.
- Confirm noRules and browser suites still pass.
